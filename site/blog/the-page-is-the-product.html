The making of

The page is the product.

Everyone else ships a PDF and calls it a library. I rebuilt the textbook from the syllabus up: 51 documents, 1,248 pages, every diagram drawn again.

The admin 19 October 2026 9 min read

There is a moment in every semester when someone asks for the notes and gets a 40 MB PDF in a WhatsApp group. The file is called unit1_final_final.pdf. It opens at 80 percent zoom. The first page is a photograph of a page, taken at an angle, with a thumb in the corner.

Everyone has a version of this file. It is how study material moves.

I wanted to see what a library looks like if you start from the other end.

The file was the wrong unit

A PDF is a file. It has a name, a size, a download button, and a share sheet. On a phone it becomes a viewer with chrome, zoom, a thumbnail panel, and a menu. You manage the file before you read the page.

For a library, that is backwards. The thing you need is the page: one screen, one diagram, the next line. The file is overhead.

Scans make it worse. A scan is a photograph of a page that was designed for print. The margins are wrong for a phone, the text is a texture, and the diagram is whatever the scanner could catch. Zooming does not add information.

A PDF is a file you keep. A page is a thing you read.

Start from the syllabus

Every document begins with the official R23 syllabus PDF. I read the unit, list the topics, and build the page around exactly those topics. The syllabus headings become the section order. The coverage table at the front of each unit is the contract: topic, section, page.

Then I set the text. Not paste it. Set it: measure, leading, a running head, a page number, a caption style, a table style. The pages are built as HTML and rendered to A4. The PDF is the master. The reader never sees the master.

The page is not a screenshot of a book. It is a page with a job.

What one page carries

Every unit opens with a cover: subject, code, regulation, unit, title, and a metadata table. After that, each page carries a running head, the section number, the page number, and a footer with the subject and unit. Tables are set with rules, not zebra stripes. Figures get a caption that says what to look at, not just what it is.

The constraint is 390 pixels. That is the width of the phone the reader is built for. If a table cannot survive that width, it is rebuilt as two tables or a list. If a diagram cannot be read at that width, it is redrawn. Nothing is shrunk until it fits.

Diagrams, not screenshots

The first drafts used screenshots of diagrams from reference books. They looked fine on a laptop and terrible on a phone: grey boxes, clipped labels, a resolution from another decade.

So I drew them. 362 diagrams as SVG: OSI stacks, ER models, AVL rotations, agent loops, Gantt charts, validation curves. Vector means the labels stay sharp, the strokes stay even, and a diagram can be redrawn for the page it sits on instead of cropped to fit.

Some are simple. Some take a full page. All of them are built from the same small set of marks: a box, a line, a label, a dashed line for a boundary. The constraint makes them look like one book instead of a collection of borrowed figures.

One page at a time

The reader is a strip of pages, not a document viewer. It requests a page when you get near it, draws it to a canvas, and drops pages that are far away. There is no text layer to select, no file to save, no share sheet. What reaches the phone is an image of the page.

Each image carries a per-reader mark, baked into the pixels before it leaves the server. At reading size it is a faint texture. In a screenshot it is still there. The mark does not stop a determined leak; it makes the ordinary leak attributable.

On a bad connection, the page is the unit that arrives. Not the file. That is the whole argument.

The shelf

Eleven subjects are set: four semesters of CSE, from ADSAA in 2-1 to Cryptography in 3-2. The counts are real: 51 documents, 1,248 pages. Software Engineering is Unit I only; the rest is still being cut.

What changes

None of this is new technology. PDFs have been on phones for fifteen years; OCR is older. What changes is the unit of design. A scan is a picture of a page designed for print. A PDF is a file you manage. This is a page designed for the phone and delivered as a page.

That sounds small until you are in a corridor with two bars, twenty minutes before a class, trying to find the one diagram the teacher mentioned. A 40 MB download fails at 80 percent. A page arrives.

The other change is that the shelf can be honest. It lists what exists. It does not promise a unit because the syllabus says it should be there. The library is small on purpose; it will grow when the pages are ready.

What’s next

The rest of Software Engineering. Assignments, so the shelf can hold the work as well as the notes. More departments when the college’s catalogue can support them. The library opens semester by semester; the shelf is loaded ahead of the doors.

If you are a NBKRIST student, the bot is the door. Open it, register once, and wait for your semester. The pages are worth it.
