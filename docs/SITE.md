# Marketing site

A separate, hand-written static site for NbkristQik. It lives inside the same
GitHub Pages project as the leaderboard app, under `/site/`.

- Live: <https://tobioffice.github.io/NbkristQik/site/>
- Blog: <https://tobioffice.github.io/NbkristQik/site/blog/>
- Source: [`src/web/public/site/`](../src/web/public/site/)

| Page | File | What it is |
| --- | --- | --- |
| Landing | `index.html` | the bot as a whole; the library is one chapter of six |
| Notes | `blog/index.html` | the index of every published note |
| Launch note | `blog/library-launch.html` | "The library is opening." |
| Making-of | `blog/the-page-is-the-product.html` | how the 51 documents were set |

The landing is about the bot, top to bottom: the hero transcript, the ledger
(9 commands, 4 mini apps, 1 roll number, 0 passwords), then chapters in
order — `01 Between classes` (`/midmarks`, `/bunk`, `/register`), `02 The
leaderboard` (the register's grammar: rings, the bracketed row, the red 75%
line), `03 The report line` (a QIK-0007 thread), `04 The library` (the
compressed chapter: cover plate, three pages, pointers to both notes), `05
The commands` (the full register table), `06 Notes`. Chapter anchors are
`#answers`, `#board`, `#library`, `#commands`; the blog nav and footers link
to these. The full shelf table and the diagram specimens live only in the
making-of post, not the landing.

## How it is built

No framework and no JavaScript. Plain HTML, one stylesheet, and images. Every
page is under `src/web/public/site/`, so Vite copies it into `dist/site/`
verbatim; `pnpm run build` is the only build step that touches it.

```
src/web/public/site/
  index.html          landing page
  site.css            the whole stylesheet
  blog/               the notes
  assets/             fonts, page renders, diagrams, screenshots, social cards
```

The design follows [`DESIGN.md`](../DESIGN.md) — paper, ink, cloth, red pen.
Zilla Slab for display, Public Sans for text, square corners, hairline rules,
tabular numerals on every figure.

## Deploying

```bash
cd src/web
pnpm exec vitest run
pnpm run lint
pnpm run build
pnpm run deploy      # gh-pages -d dist --nojekyll
```

**`--nojekyll` is not optional.** GitHub Pages builds the `gh-pages` branch
with Jekyll, and Jekyll drops a top-level directory named `site` from the
output. Without the flag the deploy succeeds, the "pages build and deployment"
run reports success, and every `/site/` URL returns 404. The flag adds a
`.nojekyll` file so Pages serves the branch as it is.

Publishing also removes the stale dotfiles that used to sit on the branch
(`.env.example`, `.gitignore`, a copy of `.github/workflows/deploy.yml`).
Those are gone; keep it that way, `.env.example` is a template and the rest
is noise.

## Assets

| Asset | Where it comes from |
| --- | --- |
| `assets/pages/*.jpg` | `pdftoppm -r 150` on the final retypeset PDFs in `NbkristQik-docs` |
| `assets/diagrams/*.svg` | the diagram sources, recoloured to the site palette (paper background, ink strokes) |
| `assets/app-reader-*.png` | 390x844 screenshots of the reader, taken from the local preview harness |
| `assets/og-*.png` | 1200x630 social cards, generated by [`src/web/scripts/og-card.html`](../src/web/scripts/og-card.html) |
| `assets/fonts/*.woff2` | copies of the app fonts, so the site needs no third-party request |
| `assets/mark.svg` | the wordmark plate, also the favicon |

The social card generator is a local tool, not part of the site:

```bash
cp src/web/scripts/og-card.html src/web/public/site/og-card.html
cd src/web/public && python3 -m http.server 8101 --bind 127.0.0.1
# open http://127.0.0.1:8101/site/og-card.html?k=<kicker>&t=<title>&s=<standfirst>&p=<plate label>
# screenshot the viewport at 1200x630, save to src/web/public/site/assets/og-<name>.png
rm src/web/public/site/og-card.html
```

## Checking a change

The site has no test suite. Check it by hand:

1. Serve `src/web/public` and open `/site/` at 1440x1000 and 390x844.
2. Follow every internal link; a broken path must not 404.
3. `document.fonts` should report `Public Sans: loaded, Zilla Slab: loaded`.
4. The browser console must stay empty.

## Numbers on the site

The site quotes real counts, so they must match the source:

| Figure | Value |
| --- | --- |
| Commands advertised | 9 (`/start /help /attendance /midmarks /bunk /register /leaderboard /report /library`) |
| Mini apps | 4 (`leaderboard, register, report, library`) |
| Subjects | 11 (CSE, R23, semesters 2-1 to 3-2) |
| Documents | 51 (Software Engineering is Unit I only) |
| Pages | 1,248 |
| Diagrams | 362 SVG sources |
| PDFs served to a student | 0 |

Command list and reply formats are quoted from `src/bot/setup.ts` and
`src/services/student.utils/formatters.ts`; the demo transcripts use the
preview roll `23CS1042`, chosen so the arithmetic is internally consistent
(139/182 = 76.37%, so `/bunk` answers "3 more").

Page counts come from the rasters under `data/pages` on the serving host, not
from a spreadsheet. If the corpus changes, the counters in `index.html` and
both blog posts have to change with it.
